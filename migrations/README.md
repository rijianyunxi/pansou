# 数据库结构基线

历史结构合并为 `044_schema.sql`，当前另有 046–052 升级脚本，由 `src/db.rs` 的 `sqlx::migrate!("./migrations")` 执行。它直接创建当前使用的表、索引、函数和触发器，以及内置默认配置；不包含旧表、历史回填、旧凭证清理或业务数据。

新数据库自动依次执行 044、046–052，后续启动通过 SQLx 校验后跳过。后续结构变更从 046 开始，不修改已经执行的 044。

本地原有数据库已完成 001–043；合并时停止服务、备份、确认其结构与 044 一致，删除被分页复合索引覆盖的 `idx_managed_resources_updated_at`，将 SQLx 历史记录切换为 044 的 SHA-384 校验值。业务数据、配置、任务和凭证完整保留。这是一次性基线切换，运行时不保留历史迁移兼容代码。

其他仍使用旧迁移记录的数据库不能直接启动新程序：必须先完成相同的结构验证和基线切换；低于旧最终版本的数据库需要先用原版本升级。不要在已有业务库执行这份建表 SQL，也不要仅为绕过错误盲目删除迁移记录。

本轮审计将 43 份原迁移在隔离空库重放，比较其最终结构、新基线结构与本地业务库结构，并比较默认配置。历史文件与审计记录已保存在 `data/validation/migration-baseline-044/`；本地升级目录另有完整数据库备份。

新增的忽略任务删除规则已折入 044 基线：`crawl_message_tasks` 只允许 parsed、empty、failed；忽略失败任务直接删除记录，不影响资源。后续编号从 046 开始，避免与本轮折入的临时 045 混淆。

046 清理四张冗余表：cloud_account_aliases、search_setting_sources、system_settings、search_settings。搜索配置更新时间迁入 policy_settings 的 search-settings-meta；实际策略值、来源启用状态及账号身份回执不变。检测关闭时删除可重建的后台待执行任务，保留手动 priority=10 与运行中的任务；重置扫描游标，重新开启后分批补任务。运行时关闭检测会每轮最多清理 1000 条后台任务。本轮后续为 047，044 保持原校验值。

047 将微信小程序配置及原更新时间完整迁入 policy_settings 的 wechat-mini，删除 wechat_mini_settings。一次性迁移旧策略字段名后删除旧键，运行时只读取当前字段名。策略保存串行合并部分更新，只写入实际变化的字段。下一版从 048 开始，既有迁移保持校验值。

048 将原始链接和检测状态合并为 resource_links，并删除资源表的链接 JSON、版本字段、绑定表和同步队列。迁移器先分页生成规范化链接输入，保留原链接 ID 对应的检测事实、任务及转存引用，再为其他资源复制独立检测事实。必须停止全部旧版写入进程后由应用执行完整升级，不能直接执行单个 SQL；首次建库没有资源时自动直接执行。主表和链接写入在同一个事务中完成，无异步同步或双存储兼容。当前共 33 张表（包含 SQLx 迁移记录），后续从 050 开始。

049 删除 resource_links_owner_key 和 resource_links_fingerprint 两张重复索引。资源内定位使用 (resource_id,position)，实时链接使用无归属行的局部指纹索引，任务按 UUID 主键定位；分页、检测和取链不依赖这两张索引。

050 新增 `crawl_message_tasks(channel_id) WHERE status=failed` 局部索引，支持总览和各频道实时查询未处理失败消息数，不修改任务或失败页面记录。

051 为消息任务增加原始 HTML 和发布时间。解析失败时保存整条消息 HTML，失败重试会更新快照；重试成功后清除原文快照，沿用成功记录每日清理和未处理失败长期保留规则。旧失败记录的原文为 NULL，需要重试采集后才能补齐；升级本身不发起网络补采。管理员详情接口按需读取原文，列表轮询不返回大段 HTML。

052 将热门词限制为最多 30 条（所有状态与来源合计），升级时一次性裁剪旧数据，之后写入触发器自动裁剪。置顶、人工及非通过状态的维护词优先保留，其余按热度、最近搜索时间和关键词稳定排序；人工维护已满 30 条时 API 拒绝新增，要求先删除一条。搜索日志不裁剪；淘汰词的累计次数通过日志恢复，已有热词继续原子递增，不覆盖人工设置。关键词等值索引支持恢复计数；热门写入共用事务锁，避免并发突破容量或遗漏历史次数。部署到已有大量热门词的环境前应备份该表。
