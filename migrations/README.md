# 数据库结构基线与升级

## 当前迁移清单

应用通过 [src/db.rs](../src/db.rs) 的 `sqlx::migrate!("./migrations")` 执行以下文件，新库按版本顺序运行：

| 文件 | 作用与注意事项 |
| --- | --- |
| `044_schema.sql` | 历史结构基线，创建表、索引、函数、触发器和默认配置 |
| `046_remove_unused_settings.sql` | 清理冗余配置表，保留实际策略与账号身份；关闭检测时清理可重建的后台任务 |
| `047_unify_wechat_settings.sql` | 将微信配置迁入 `policy_settings` 的 `wechat-mini`，删除旧表 |
| `048_resource_owned_links.sql` | 将原始链接与检测状态统一到 `resource_links`，删除旧链接 JSON、绑定表及同步队列 |
| `049_trim_resource_link_indexes.sql` | 删除重复链接索引，保留资源顺序、检测调度和 UUID 定位索引 |
| `050_crawl_failed_message_index.sql` | 增加未处理失败消息局部索引 |
| `051_crawl_failed_message_content.sql` | 为失败消息保存原始 HTML 和发布时间，重试成功后清除原文快照 |
| `052_hot_search_retention.sql` | 热门词最多保留 30 条，升级时裁剪旧数据；搜索日志不裁剪 |
| `053_cloud_qr_settings.sql` | 迅雷实验扫码设置存入账号表，默认关闭；敏感上下文只写不回显，支持配置版本校验 |

没有独立 `045` 文件；其临时变更已折入基线。后续迁移从 `054` 开始，不修改已发布文件的内容或校验值。

`044` 是结构基线，不是最终状态的独立快照：新库也必须继续执行 `046–053`，不能只运行 `044`。应用启动会校验 SQLx 已执行迁移的 SHA-384 校验值。

## 新数据库

1. 按根目录 `.env.example` 配置独立 PostgreSQL 与 Redis。
2. 启动应用，由迁移器执行完整清单；不要手工挑选单个 SQL 文件。
3. 检查启动日志、迁移版本和服务健康状态，之后再导入业务数据。

构建和默认单元测试不要求连接数据库；启动应用会执行迁移，不是只读检查。API 和各 Worker 模式都会初始化数据库。

## 已使用 044 基线的数据库

1. 停止旧 API、采集、链接和凭证 Worker，确保没有旧版写入进程。
2. 备份完整 PostgreSQL 数据及迁移记录，并确认备份可恢复；备份包含网盘凭证，应限制访问。
3. 在数据库副本演练，用目标版本应用执行尚未执行的升级脚本。
4. 核对资源、链接、来源、任务、策略、账号绑定及失败消息状态后，再升级业务库。
5. 所有进程使用同一版本和新结构，不混用旧程序。

`048` 必须由应用执行完整升级：Rust 迁移准备逻辑会分页生成规范化链接输入，保留检测事实、任务及转存引用。直接执行单个 SQL 缺少这一步。新库没有资源时无需生成历史输入。

`051` 不会主动重新抓取历史失败消息，旧失败记录原文为 NULL，重试采集后才能补齐。

`052` 会一次性裁剪热门词，应在演练中核对要保留的人工、置顶及审核项；人工维护项已满 30 条时 API 要求先删除再新增。

## 使用 001–043 等旧迁移历史的数据库

**不能直接启动当前程序。**当前仓库不再携带旧迁移链，也不保留运行时旧结构兼容层。

- 先确定实际迁移版本；尚未达到旧版最终结构的库，需要取得对应旧版代码及完整迁移链，在隔离副本逐步升级。
- 达到旧版最终结构后，停止全部写入、备份并逐项比较表、列、类型、约束、索引、函数、触发器及配置与 `044` 基线的差异。
- 只有结构验证通过，才能设计并审核 SQLx 基线记录切换；之后还要用当前应用执行 `046–053`。
- 不要在已有业务库执行 `044` 建表 SQL，也不要为绕过错误盲目删除或改写迁移记录。
- 不确定旧结构时停止升级，保留原库和备份，不能仅凭版本编号或开发者曾经完成的本地升级认定兼容。

历史迁移审计与数据库备份不包含在本仓库；`data/` 是忽略目录。不要假定克隆代码后就拥有旧迁移文件、校验值或可恢复备份。

## 隔离验证

仅在可丢弃的专用测试库上配置以下变量：PostgreSQL 数据库名必须以 `_test` 结尾，Redis 必须使用独立非零 DB，禁止指向业务环境。

```powershell
$env:PANSOU_TEST_DATABASE_URL = 'postgres://TEST_USER:TEST_PASSWORD@127.0.0.1:5432/pansou_test'
$env:PANSOU_TEST_REDIS_URL = 'redis://127.0.0.1:6379/15'
cargo test --locked -- --include-ignored --test-threads=1
```

默认 `cargo test --locked` 跳过这些外部服务测试。测试会改写测试库数据，且不代替真实旧库升级演练。
