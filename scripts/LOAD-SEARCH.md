# 10 分钟搜索压测

需要 Node.js 20+，仅使用内置模块，无需安装 npm 依赖。可把 `load-search.mjs` 单独复制到另一台机器运行。建议从服务器以外的机器运行，避免压测客户端消耗被测服务器资源。

默认目标为 `https://pan.letus.lol`。从项目根目录执行：

```bash
node scripts/load-search.mjs
```

默认持续 600 秒，每 600 毫秒启动一个独立匿名用户，共 1000 人。每个人先 GET `/api/account/session` 获取自己的 Cookie，再 POST `/api/search`，请求体为 `{"kw":"搜索词"}`，持续读取 SSE 直到流结束。不使用 GET 搜索，也不调用 `/api/search/json`。每个词在本次运行中仅出现一次，无自动重试。

100 人/分钟是用户到达速率，不是固定 100 并发。搜索变慢时在途用户数会增加；会话初始化还会产生约 100 次请求/分钟。默认单用户全流程超时 120 秒，因此 10 分钟发起完成后，最多再等待约 120 秒收尾。并发上限默认 500，达到后记录跳过，不延迟补发来掩盖负载不足。

部署完成并调整好应用及反向代理的限流后再运行。脚本不会改服务器配置，也不会自动清空缓存。独立会话仍共用运行机器的出口 IP。

## 参数

仅预览计划，不发网络请求：

```bash
node scripts/load-search.mjs --dry-run
```

先做 1 分钟、10 人的小流量试跑：

```bash
node scripts/load-search.mjs --duration-seconds 60 --users-per-minute 10
```

指定完整配置和报告目录（目录必须尚不存在）：

```bash
node scripts/load-search.mjs --url https://pan.letus.lol --duration-seconds 600 --users-per-minute 100 --timeout-seconds 120 --output load-reports/production-run-01
```

内置词库采用影视、纪录片、课程名称和“高清”“全集”“入门教程”等修饰词组合。它模拟不重复的长尾搜索，可能出现较多零结果，不代表线上真实用户搜索分布。可以用真实关键词替代：准备 UTF-8 文本，每行一个词，去空白和去重后至少有 1000 个，每个不超过 100 字符。

```bash
node scripts/load-search.mjs --keywords ./my-keywords.txt
```

脚本会随机打乱关键词，再保存实际采用的 1000 个查询。重复运行默认不保证与上一次的关键词不重叠。需要完全控制词表时，传入恰好 1000 条不重复关键词。

## 报告

默认输出到 `load-reports/<UTC时间>/`：

- `report.md`：中文报告，包含整体及每分钟成功率、错误、耗时 P50/P95/P99、零结果数、并发峰值。
- `summary.json`：机器可读汇总，包含耗时样本数、HTTP 状态和错误分类。
- `requests.jsonl`：请求逐条记录，完成一条写一条，包含开始/结束时间、Session ID、关键词、耗时、SSE 接收字节数；不保存 Cookie 或搜索结果内容。
- `keywords.txt`：本次实际使用的唯一关键词列表。
- `plan.json`：运行参数。

每 10 秒输出一次进度。Ctrl+C 会停止发起新用户，取消在途请求，然后生成已有数据的报告；强制杀进程或断电无法保证生成汇总，但已写入的 JSONL 仍在。

退出码：0 = 正常完成且无失败；2 = 存在失败、超时或并发跳过；130 = 手动中断；1 = 参数或运行错误。

“完整成功”要求 HTTP 成功、收到 `complete` 且 `code=0`，随后正常结束 SSE。HTTP 200 但流中断算失败。零结果仍算成功，单独列出。每分钟统计按计划启动分钟归组，因此会包含在后续分钟才结束的请求。首结果耗时只统计收到非空结果的请求，成功搜索耗时只统计成功请求；同时查看全部搜索耗时和失败率以避免幸存者偏差。

这是一台客户端发起的匿名搜索流程模拟，没有浏览器页面渲染、静态资源加载、登录或连续多次搜索。当前 SSE 不提供所有来源的诊断信息，因此不能推断每个上游的成功率。报告不采集服务器 CPU、内存、磁盘或网络利用率；请使用报告的 UTC 开始/结束时间对照服务器监控（北京时间为 UTC+8）。
