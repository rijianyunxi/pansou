# 资源与链接存储优化

日期：2026-10-03。新迁移：029。本地开发库已应用，新 debug 后端已加载新代码。

## 最终数据归属

| 对象 | 保存位置 | 说明 |
| --- | --- | --- |
| 资源标题、描述、标签、图片和资源创建时间 | `managed_resources` | 一条资源记录 |
| 当前编辑输入中的链接数组 | `managed_resources.links_json` | 只保存 type/url/password，不保存客户端提交的检测结果 |
| 每条链接的创建时间、有效性、检测时间、重试时间和错误码 | `link_catalog` | 检测事实的唯一来源，同地址不同提取码分别匹配 |
| 资源在各频道消息里的展示快照 | `resource_occurrences.result_json` | 保护频道授权范围，保留同一资源的不同来源展示 |
| 资源/消息范围对应哪些链接档案 | `resource_link_bindings` | 多来源引用同一链接检测事实，不复制检测状态 |
| 资源整体有效性 | `managed_resources.link_validity` / `link_validity_updated_at` | worker 维护的汇总缓存；后台读取时按当前每条链接的事实重新汇总，过期事实不算有效 |
| 资源所属网盘类型 | `resource_cloud_types(links_json)` | 从实际链接推导，排序、去重；不再单独保存数组 |

资源主表由 **23 列减为 19 列**。删除 `cloud_types_json`、`check_status`、`check_message`、`checked_at`，资源的 `created_at` 保留。每条链接自己的 `created_at` 原本就保存在 `link_catalog`。

删除无生产读取入口的历史 `resource_links` 表，并移除采集中的重复 INSERT/UPDATE/DELETE。迁移前它约占 **179MiB**。未移除资源输入、来源快照、链接档案、绑定或任务；单条链接仍以关系表中的行维护。

`links_json` 保留为编辑/来源展示输入。目录与绑定目前由持久化 outbox 同步，不能依靠尚未同步的目录反向重建最新编辑内容。此次没有把不同频道的链接合并成资源的全局链接，亦没有采用每个网盘一个物理列的宽表。

## 查询、写入和接口

- 后台创建/编辑仅写链接，忽略旧请求里合法但不一致的 `cloud_types` 声明，实际类型由链接确定；不合法的类型数组仍返回 400。链接必须符合数组结构。
- 后台回传的 `validity`、`checkStatus`、`checkMessage`、`createdAt` 等观察字段在保存时剥离；它们不能通过编辑请求篡改链接档案。
- 搜索的人工覆盖展示、资源列表/详情、类型筛选均使用派生类型。来源快照的展示和频道隔离保持原查询语义。
- 用 `resource_cloud_types(links_json)` 的 GIN 表达式索引代替旧数组索引；类型计数表由链接变更、软删除和恢复事务内维护，仍支持精确的类型总数及小表下拉选项。
- 后台列表、详情和保存响应按链接指纹一次批量读取目录观察，不注册链接、不创建检测任务。空链接资源和目录未同步的链接仍显示未知。
- 每条后台链接增加 `createdAt`、`checkStatus`、`checkMessage`，保留原 `validity`、`checkedAt`、`lastAttemptAt`、`reasonCode` 等字段。目录尚未登记的链接，`createdAt` 为 null，避免用资源创建时间冒充链接创建时间。
- 检测说明采用固定、可读的错误码映射，不保存上游任意错误文字。最新失败尝试的说明优先于旧检查的过期说明。
- 资源级兼容字段 `checkStatus`、`checkMessage`、`checkedAt` 由链接当前事实生成；数据库只维护一套汇总有效性。
- 链接详情抽屉显示独立的入库时间和检测说明。公开搜索响应仍使用授权后的链接引用。

## 验证与实际运行

- 开发库迁移前核对 399,082 条资源：原类型数组与链接推导出的排序去重数组差异为 0；原检查状态与有效性汇总差异为 0，旧检查说明非空记录为 0。
- 新增迁移保护测试：在隔离 schema 中执行 001–028，构造公开/私有来源、多链接、多提取码、历史链接表和队列，再应用 029。比较资源保留字段、来源快照、目录、绑定、任务、搜索投影和频道统计，全部一致。
- 覆盖重复网盘类型、声明但不存在的类型、无链接、自定义类型、真实编辑/无变化编辑、禁用、软删除/恢复、链接修订与有效性重置、事务回滚。
- 新增后台 HTTP 测试：创建、编辑、详情、旧类型声明不一致、伪造检测观察剥离、过期目录与 stale 资源汇总、每条链接创建时间、错误结构 400、只读详情不注册链接。
- 搜索新旧查询对照、采集、频道权限、消息管理、频道删除保留资源、类型统计、任务中心、队列调度及租约回归通过。
- 原生云盘批量检测/持久化幂等测试在独立测试库中通过；检测仍写每条链接的目录事实，并更新精简后的资源汇总。
- 最终普通后端测试 **108/108** 通过；27 项数据库/Redis测试默认忽略，相关项已显式执行。前端相关测试 **13/13**、前端 typecheck、debug 构建和 `git diff --check` 通过。
- 全部外部环境测试串行共用一个测试库时，观察到 **129/134** 通过；失败涉及原生云盘、监控、扩展网盘、公共交付、超时等待。原生云盘在独立库中通过，其他共享账号/策略状态及异步问题在上一批验证中已记录，并非完整套件全绿。新增最后一项诊断单元测试后，普通测试总数为 108。

真实数据性能副本包含资源、历史链接、类型计数、目录和迁移记录，未启动 worker；它不是完整业务副本。迁移 029 约 **4.194s**。初步观察：无筛选第一页 SQL 约 1.994ms、夸克第一页约 1.341ms；空稀有类型走新 GIN 索引约 0.035ms。这些是单次观察，缓存与数据布局影响结果，不承诺接口 P95。

本地开发库在停止旧 API 和内嵌 worker 后应用迁移 029，迁移记录耗时 **7349ms**。重新启动时保留原进程的启动环境，端口仍为 3666，原 worker 配置继续加载。健康接口 `/api/health` 返回 200、status=ok。

迁移后开发库只读核验：399,091 条资源，派生类型与计数元数据差异为 **0**；新表达式索引 valid，约 **960KiB**。无筛选第一页 SQL 观察约 **0.881ms**；稀有类型空结果实际走新 GIN 索引，约 **0.047ms**。行数变化来自正在运行的采集，不能作为迁移新增或删除资源的证据。

删除列不立即重写主表回收旧元组中的空间，本次没有执行 VACUUM FULL。历史链接表的约 179MiB 是明确移除的存储，不将它与整个数据库文件大小的即时净变化混为一谈。
