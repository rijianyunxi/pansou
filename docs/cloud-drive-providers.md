# 网盘交付与清理管理

后台 **链接后台处理 → 链接清理**（`/admin/tasks?kind=cleanup`）支持状态筛选、分页、查看产物清单和重试；旧 `/admin/link-cleanup` 地址重定向到该分类。运行监控的“清理失败 / 阻塞”提示直接进入该分类。重试只重新入队，保留撤销分享的进度；尚未到期、执行中的有效租约和已完成任务不能重试。账号不一致、归属不明或清单被修改时仍会阻塞，没有强制删除或清空回收站入口。

清理页可按网盘筛选，筛选条件和页码保存在 URL。页面可见时每 10 秒更新，打开详情或确认框时暂停；加载失败保留上一份结果并禁用重试，避免误操作过期状态。详情显示清理到期时间、不能重试的原因，并按每批 50 条展开文件清单。登录/权限失败、超时、账号忙与归属校验失败分别提示处理建议。

## 五个平台

百度、夸克沿用 Cookie。阿里、迅雷、光鸭新增原生 HTTP 适配器，通过固定官方 API 地址完成分享读取、目录选择、按需转存、创建分享、撤销分享和清理。所有平台使用同一套异步取链、结果防覆盖、专用子目录和持久化清理队列。

在「系统 → 网盘账号」的对应卡片上保存账号凭据并检测登录态，然后点击卡片上的「转存」，在弹窗中选择项目专用目录、设置清理时间并开启转存。新平台默认关闭。仅保存凭据不会自动开启转存。

新增平台凭据使用 JSON，不能只填 refresh_token。例如：

```json
{"access_token":"官方网页登录访问令牌","user_id":"官方账号接口返回的账号ID","drive_id":"阿里云盘drive_id","device_id":"设备ID","signature":"阿里网页登录请求的x-signature"}
```

迅雷使用 `access_token`、`user_id`、`x-captcha-token`、`x-device-id`、`x-client-id`；光鸭使用 `access_token`、`user_id`、`device_id`。可使用对应的 snake_case / camelCase 别名。`user_id` 不是昵称，迅雷或光鸭账号响应中的 `id` / `sub` 也可以作为这个值。配置只返回“是否已配置”和字符数，不回显凭据。

本版本不自动刷新令牌。访问令牌、设备签名或验证码令牌失效时，需在官方客户端完成验证并更新后台配置。光鸭可另外填写 `x-device-sign`。更新同一账号令牌不会改变产物归属（阿里还需保持同一 `drive_id`）；每次云端写入和清理前都通过官方账号接口核对实际登录账号。更换账号后不能清理旧账号产物，需要恢复原账号有效凭据。

## 超时、失败与安全边界

- 前台请求等待至多约 500ms，未完成时返回 202、requestKey 和实际 stage。网页、小程序按 pollAfterMs 查询同一操作；后台处理窗口为 120 秒，客户端等待窗口为 150 秒。排队、读取、转存、分享或验证已有分享分别展示；不伪造完成百分比。
- HTTP 响应窗口不会中断转存。后台处理期限耗尽才回退原链接；已发出的写请求继续确认并保存归属证据，超时后禁止继续发起新写操作，晚到产物进入清理。关闭页面只停止查询，重试复用未完成的 requestKey，不重复转存。
- 光鸭、迅雷复用转存适配器刚核验过的根目录清单，后代目录与后续清理仍实时读取。异步任务先按 250ms、500ms 查询，再退避至 1 秒，短任务减少等待且长任务保持有限频率。
- 迟到的转存、空目录或分享记录立即进入到期清理队列。清理先撤销已确认的分享，再核对完整文件清单并删除本流程子目录。
- 阿里多文件逐项转存时，超时可中止后续复制，已成功复制的准确 ID 单独记录并清理。
- 已经交付过的缓存不会因另一请求超时而提前清理。账号暂忙时 10 秒后重试，不消耗失败次数。
- 丢失响应、任务状态不明、未确认文件清单时保留记录并阻塞，不能以“超时”作为盲删依据。管理页面提供重试，但不会跳过归属验证。
- 新平台清理优先移入回收站，不清空回收站。任意公开分享不作为删除他人文件的归属证明。
- 每次撤销分享或删除前核对任务租约，失效的旧任务不能继续发出写请求或覆盖新任务结果。队列时间异常时也不能提前清理未到期产物。
- 令牌型平台不会把响应 Set-Cookie 合并进 JSON 凭据；未知业务状态、缺失文件类型/大小按未确认处理。迅雷、光鸭的转存清单逐项匹配，每个来源只能被匹配一次。
- 光鸭目录列表按官方客户端的请求形态发送：不带 `fileTypes` 字段（空数组与"不过滤"不是同一个请求）。上游返回非 2xx 时记录状态码；响应缺少 `code` 业务信封时记录顶层键名，便于区分"请求被拒"与"上游故障"。
- 光鸭的信封并不统一：失败响应带 `code`（令牌无效时 HTTP 401 + `code:117`），但线上**成功的业务响应是 `{"data":…,"msg":…}`，没有 `code`**。参考客户端从不读业务码，只依赖 HTTP 状态，所以缺 `code` 本身不能判定失败。服务端只在响应确实携带业务载荷（存在非 null 的 `data`）时才接受这种响应；只有 `{"msg":…}` 或 `data:null` 仍按失败处理，`code` 存在时依旧以它为准（`0` 与光鸭的 `200` 视为成功）。

适配器通过本地模拟上游测试；这些测试不证明真实账号权限、平台风控或当前凭据有效，需要配置账号后通过“检测登录态”并完成真实联调。

## 接口契约来源

- [阿里 PDS 分享、share token 与 CopyFile 官方说明](https://help.aliyun.com/en/pds/drive-and-photo-service-dev/user-guide/file-sharing-related-operations)，结合 [aligo 客户端实现](https://github.com/foyoux/aligo)。消费端使用官方阿里云盘固定 API 域名，不能配置任意 PDS 域名。
- [迅雷请求与转存/分享接口客户端实现](https://github.com/ctwj/urldb/blob/main/common/xunlei_pan.go)，[OpenList 迅雷浏览器驱动](https://github.com/OpenListTeam/OpenList/tree/main/drivers/thunder_browser)。
- [光鸭客户端实现](https://github.com/DDSRem-Dev/guangyaclient/blob/master/guangyaclient/client.py)。

第三方平台接口可能变化。缺少业务状态、任务完成确认或文件身份时按失败/未知处理，不伪造转存成功或判定链接失效。
