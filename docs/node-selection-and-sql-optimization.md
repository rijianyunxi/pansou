# 节点选择、名称搜索与 SQL 优化

实施日期：2026-09-30。当前数据库为 PostgreSQL + Redis，不是 MySQL。

## 1. 节点配置

- 实时资源来源、TG 频道、TG 默认配置共用同一个 shadcn 节点选择编辑器。只勾选节点、填写整数权重；不再暴露策略模式、随机分配、回退开关、位置和重试次数。
- 权重范围 0～10000，越大越先尝试；同权重按节点 ID 倒序。最多选 50 个节点。权重 0 仍是有效候选，不代表停用。
- direct 是数据库中的内置只读节点，不能改名、禁用或删除。不勾选 direct 就不允许直连；勾选后也按照权重排序。
- GET/HEAD 遇到可恢复失败可继续下一个选中节点，每个节点只尝试一次，共享总超时预算。POST 不自动重放。429/不可恢复 4xx 不通过轮换节点绕过限制。
- 额度请求前原子预留，半开熔断探测保留租约，停用/配额耗尽/熔断中的代理不参与实际发送。
- TG 自动注册频道仍可在内部继承 TG 默认节点；页面展示默认的实际候选。修改勾选或权重会为该频道保存独立配置。默认缺失时拒绝出站，不偷偷直连。
- 配置保存带版本校验，冲突返回 409。版本和节点成员使用同一 MVCC 快照。节点引用只读，被引用的代理不可删除。

### 008 迁移

008_weighted_nodes_and_query_optimization.sql 保留原代理权重；原纯直连配置转为 direct 权重 10。原代理配置允许直连回退的，补一个权重 0 的 direct。旧 position/概率随机/回退字段删除，节点排序替代复杂策略。部署时先停止旧 API 和 worker，备份数据库后再用新程序升级，禁止旧 worker 与新 schema 混跑。

## 2. 只匹配资源名称

- 本地 TG 搜索对当前用户可见的资源 name 做大小写不敏感的子串匹配；description 和 tags 不参与命中，但仍完整保存和返回。
- 后台资源列表的关键字筛选也只匹配 name，输入框和空状态说明已同步。
- 同一个资源在不同频道有不同标题时，候选 gram 覆盖各个已解析关联的标题；最终查询只使用授权频道的 presentation.name 校验和展示，其他频道标题不能造成越权命中。手动覆盖资源使用覆盖后的名称。
- 本地批次先返回，再逐个返回实时 HTTP 来源；这次不重定义第三方网站自己的搜索规则，实时来源可能由其上游匹配描述。
- 缓存身份增加 match=name-only-v1，索引版本在迁移时递增，避免复用描述命中的旧结果。

### 009 迁移

009_name_only_search_index.sql 只清空并重建派生 resource_grams，以资源名称和可用关联标题生成单字/双字 Unicode gram；同时更新手动资源索引触发器和后台名称 trigram 索引。不清空业务资源、描述、原消息或关联表。现有资源更新和后续采集均只维护标题 gram。第一次启动需要等待索引重建完成再启动 worker；不要把迁移期的暂时无监听误判为启动成功。

## 3. SQL 与写入优化

- 频道列表先分页，再用批量 SQL 取消息/失败/资源统计和最新任务；策略、成员和默认策略也一次批量读取，取消逐频道 N+1。
- 新增活跃资源、频道-资源关联、最新任务、节点引用索引；统计 DISTINCT 标识使用 C 排序规则。
- TG Rust 写入索引，数据库触发器只处理手动资源/覆盖，避免重复构建。重解析内容完全一致时，不更新资源、链接或 gram。
- 锁定当前资源行后比较字段元组；链接和 gram 只删除失效项、补新增项，保留未变的行，减少 WAL、死元组和索引膨胀。
- 实际库只做普通 VACUUM ANALYZE，没有做会强锁整表的 VACUUM FULL，没有清空 Redis。

## 4. 实测与验收

频道统计 SQL 在同样维护后、约 8 万条消息/4.4 万资源的本地样本：旧 SQL 184～187ms，新 SQL 115～125ms。恢复 worker 后样本 SQL 116～134ms，频道列表整次 HTTP 208～260ms。早期未维护旧 SQL 287～352ms，不能把维护收益全部归于 SQL 改写。这是本地样本，不代表百万级压力测试，也不表示所有慢 SQL 都已消除。

- Rust 单元/契约/解析测试：41 通过，2 个需外部服务的集成测试默认跳过；专用 _test 数据库另跑这 2 个测试，全部通过。
- 前端 41 个测试通过，vue-tsc 类型检查与 Vite 生产构建通过。
- 集成测试覆盖名称/描述/标签的匹配边界、管理员资源筛选、频道隔离、节点优先级和 direct、POST 不重放、原子额度、内置节点保护、频道批量统计以及相同内容重解析的 CTID 保持不变。
- 后台节点编辑器桌面/320px 窄屏检查，弹层字段可滚动、底部动作可达；首页展示样式不在本次修改范围。

真实 009 升级冻结后共 85,269 条消息、46,091 条资源、80,696 条关联。升级后数量、内容摘要和频道断点全部一致。派生 gram 从 11,706,445 条降至 1,570,918 条，表及索引总占用从 3.65GB 降至 0.383GB（约减少 89.5%）。真实后台与 TG-only /api/search 验证：有 187 条资源描述包含“大学士府”而标题不包含，该关键词搜索为 0；“兰香如故”正常返回，所有标题均包含关键词，描述保留。无 Session 搜索返回 401，API/PostgreSQL/Redis 健康，worker online。

真实升级前冻结业务写入并 pg_dump；对消息、资源、关联表的数量与内容摘要、频道采集断点逐项对比，再启动 worker。数据库备份、测试凭据、截图和临时代理均不纳入 Git。
