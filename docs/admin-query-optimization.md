# 后台资源、搜索日志与统计缓存优化

## 最终行为

- 资源和搜索日志列表返回 `hasMore`、`nextCursor`。客户端把上一页的游标作为 `before` 传回；游标查询不执行 OFFSET，按 `(updated_at,id)` / `(created_at,id)` 的倒序元组继续。
- 游标绑定列表种类、筛选条件和每页条数；错误、跨列表、跨筛选条件、非数字日志 ID 和过长游标返回 400。登录和管理员校验仍在游标处理前执行。
- 每次多取一条判断是否有后续页；总数仍按整个筛选条件计算，不按游标截断。资源总数沿用原来的 30 秒缓存与网盘类型增量计数，日志总数仍为精确查询。
- 网页的连续翻页、访问过的页可复用游标；未访问过的指定页码仍使用索引上的 OFFSET。页码跳转、每页数量、原有响应字段继续兼容。
- 修改资源、修改筛选、每页数量变化、刷新或删除日志后丢弃旧游标；资源列表取消过时请求，避免晚到响应覆盖当前页。客户端最多保留 256 个分页锚点。
- 游标不是静态数据快照：新插入的顶部记录不会挤动已拿到的下一页，但资源被编辑后可能改变排序。刷新可以重新获取当前结果。

## 搜索日志查询

筛选条件由 QueryBuilder 按需生成，不再为每个未使用的参数附加 `OR`。用户 ID、会话、搜索范围和时间限制可直接使用现有索引。计数/分页候选查询只在文字或 IP 筛选需要用户资料时关联 users；取出本页 ID 后再加载日志详情、用户名和昵称。

保留关键词在 keyword、username、nickname、有效 IP 上搜索的语义，也保留 unknown/空 IP 回退到用户最后登录 IP 的行为。跨字段的文字匹配仍有 OR，没有为了命中单个索引缩减查询范围。

迁移 030 以 `(created_at DESC,id DESC)` 索引替换旧的时间单列索引，支持完整稳定排序与元组条件。现有用户/会话/范围组合索引不重复添加。日志目前只有约 46 条，收益主要面向后续增长，不能把合成数据结果当作线上接口提升。

资源名称索引 `idx_resource_name_admin` 在迁移 009 已存在，本次执行计划确认使用该 GIN 索引，无需重复创建。此前仅从少量迁移推测“可能没有名称索引”的判断已修正。

## 统计缓存

注册表锁只用于查找每个条件的缓存槽，不跨数据库查询持锁。相同条件的并发请求共享一次成功刷新；不同条件、已有缓存命中可以独立处理。

保留 64 个缓存槽上限；满额时淘汰无人使用的槽，全部忙碌时新条件不进入缓存。错误和取消释放该条件的锁，下一次可以重试。失效操作直接移除槽，旧的在途请求不能把结果写回新一代缓存。

## 回归与隔离入口

`scripts/test-db-isolated.py` 使用本地 compose PostgreSQL，逐项创建 `_test` 数据库，建立专用 Redis 容器，并为每项提供随机临时凭证加密密钥。每项结束删除测试库，最终删除测试 Redis；不会复用应用数据库、Redis 或凭证文件。

```sh
python3 scripts/test-db-isolated.py
# 也可给出准确的 Rust 测试名称，只跑对应集成测试。
```

有自定义 PostgreSQL 测试凭证时设置 `PANSOU_TEST_DATABASE_URL`（本地地址且库名以 `_test` 结尾）；容器与管理角色可通过 `--postgres-container`、`--postgres-user` 指定。日志保留在系统临时目录。

已查明的测试问题：

- 之前共享测试库遗留的账号授权与提供商策略会影响后续转存/分享用例；公共交付、百度/夸克原生接口、阿里/迅雷/光鸭转存复用和迟到产物清理在独立库回归。
- 监控用例先恢复检测，再断言仍暂停，缺少中间的暂停操作；已补充显式暂停，继续检查提供商策略保存不会改变该状态。
- 加密授权测试要求显式测试密钥；单条手工检查测试要求 Redis DB 15。隔离入口统一提供这两项环境。
- 清理到期判断统一使用数据库 `clock_timestamp()`，与队列调度采用同一时间来源，避免跨进程时钟差造成刚到期任务被延期。
- 超时清理在晚到写入释放账号锁时允许 `cleanup_busy` 延后十秒。迟到请求的最终落库也可能短暂锁住队列行，`SKIP LOCKED` 可以让一次调度不取任务。测试确定性持有队列行验证该情形，并等待未领取或账号忙这两种合法调度结果，设 12 秒上限；其他所有清理错误立即失败；仍断言只撤销自己的分享、只删除自己的目录、原有文件保留且最终任务完成。

新增用例验证并发相同/不同条件、慢查询不阻塞命中、刷新时失效、取消后重试、缓存容量；后台 HTTP 验证同时间排序、游标与页码等价、完整遍历无重复、筛选绑定、权限、插入顶部记录后续页稳定和日志时间/IP/用户筛选。

## SQL 观察

真实开发库约 39.9 万条资源，在同一只读重复读事务中观察：取第 20,001 条起的 21 个键，OFFSET 扫描 20,021 条，约 16.277 ms；已知锚点的游标扫描 21 条，约 0.163 ms。这里只测候选 ID SQL，游标的首次获取和接口统计/详情成本不包含在内，不能等同接口 P95。

20 万条合成日志，每五条共享时间戳：深页 OFFSET 约 19.837 ms；时间单列索引的游标查询约 0.042 ms，并执行增量排序；新组合索引首次访问约 0.076 ms，直接 Index Only Scan 命中完整元组条件，无额外排序。新索引的价值是完整排序/过滤路径，不宣称该次冷缓存数字更快。

复现查询见 `sql-admin-page-benchmark.sql`。
