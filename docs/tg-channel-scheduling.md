# TG 频道采集与独立实时搜索（2026-10-01）

本文替代旧 TG 工作台文档中的公共搜索身份、用户频道采集租期、500 页预算、近期更新复查、原文重解析和归档方案。

## 两条完全独立的路径

- 系统频道：管理员在 TG 采集页维护 → Worker 抓取 → PostgreSQL 入库 → 搜索从 PostgreSQL / Redis 本地索引获取。暂停只停止采集，不隐藏已入库资源。不存在公共搜索身份或绑定。
- 自定义频道：本次请求的 channels → 规范化、去重及配额校验 → 仅请求这些公开频道的 TG 搜索页面 → 通用 transform → 返回结果。不使用保存的频道列表替换请求，不登记采集频道，不查询资源库/结果缓存，也不调用系统资源源。
- 自定义搜索仍保留 Session、权限、限流、通用模板配置及搜索日志；这些不是资源查询或采集逻辑。
- 搜索仍不返回原 URL/提取码。自定义结果的链接能力引用在进程内短暂保存（30 分钟，上限 10000 个、编码内容 64 MiB），不写资源 DB/Redis。服务重启后须重新搜索；多 API 实例需要会话粘滞。打开/复制仍共用链接获取接口。

## 三项全局配置

| 字段 | 默认 | 范围 | 含义 |
| --- | --- | --- | --- |
| concurrentChannels | 3 | 1–32 | 所有 Worker 合计同时处理的频道数 |
| pageDelaySeconds | 3 | 0–3600 秒 | 同频道每页完成后，下一页启动前等待 |
| dailyIntervalSeconds | 300 | 60–86400 秒 | 一轮日常增量完成后的间隔 |

设置保存在 crawl_settings 单行表，GET/PUT /api/admin/crawl/settings。version 必须带回 PUT，版本冲突返回 409。调低并发不取消已执行页面，只限制后续领取。HTTP 限频退避优先于普通等待。

## 编排

1. 启用新频道后自动获取最新页，建立 newest_message 检查点。
2. 自动启动历史全量，沿 Telegram 实际 before 游标连续向前，不限制总页数。每页消息、资源、游标和进度在同一事务提交。
3. 历史补齐期间，到期的日常增量优先插入；同频道始终只有一个执行页。日常增量追到上次同步检查点后结束，历史从自己的游标继续。
4. 可识别消息且确实没有上一页时，history_complete=true；后续只做日常增量。无法识别页面、权限/网络错误不视为历史完成。
5. 进程中断后从 durable cursor 继续，过期租约重新领取。全局领取事务锁与同频道运行唯一约束防止多 Worker 超额或重复执行。

“全量”指公开 TG 网页实际可访问的所有消息，不能恢复私有、删除或上游不可访问的消息。

## 失败页与待复核

- 网络异常先自动退避（遵守 Retry-After），最终未成功的请求进入失败页队列；解析异常保存成功部分并记录失败页，原扫描可以继续。
- crawl_page_failures 保存 channel_id、job_id、kind、cursor_before、next_cursor、page_number、last_error、retry_job_id 及时间。
- 页面序号仅用于展示；实际重试依据原 before 游标。retry 单页任务重新 HTTP 抓取、按当前规则解析入库，成功删除失败页记录。原任务因抓取失败而中断时，使用这次重试的下一页游标继续，不重复请求已成功重试的页。
- 忽略物理删除所选失败页记录，不删除资源/消息，不伪造历史完成。若原抓取连下一页游标都没取得，原历史任务仍中断，需在任务详情继续重试；不能猜一个页跨度静默跳过未知边界。
- 批量请求属于频道：POST /api/admin/crawl/channels/{channel}/failures，body 为 {action:"retry"|"ignore",ids:[...]}，最多 100 条。越频道/已删除/正在重试的记录返回 409，整批不部分提交。
- GET 同路径按 id 游标分页，最多 100 条；before 指定下一批。任务详情与待复核嵌入频道行，提供勾选、一键重试、一键忽略，无独立任务/复核 Tab。

## 并发提交修复 013

HTTP 页面抓取仍按全局频道并发执行。入库事务、资源修改触发器、资源关联写入和链接同步队列统一先锁 local-index 版本行，再处理资源/关联/队列，避免两个频道交叉更新相同资源导致死锁。频道配置与页面提交先锁版本行再锁频道，页面失败回写也遵循频道先于任务的锁顺序。 migration 013 只调整触发器，不删除业务数据。
