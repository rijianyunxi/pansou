# 节点库与业务出站策略分离设计

> 2026-09-30：本轮核心范围已实施。本文保留需求设计背景；实际组件、接口、迁移和验收差异以 `tg-workbench-implementation.md` 为准。直连回退拆分为无可用节点 / 尝试失败两类，末位直连伪节点可精确自动迁移。

- 日期：2026-09-30
- 状态：本轮已实施，旧策略组与路由已迁为单对象出站策略。
- 本文替代 TG 工作台方案中“节点页定义策略、频道选择共享策略”的旧提议。

## 1. 决策

采用“全局节点库 + 业务对象自己的出站策略”。

- `/admin/proxies` 只管理节点本身，不创建策略、不选择来源、不维护路由优先级。
- `/admin/sources` 在每个实时来源中配置出站方式、参与节点与调度/回退规则。
- `/admin/crawl` 在每个 TG 频道中配置相同的出站策略；实际仅供 worker 抓取使用，TG 本地数据库搜索不走代理。
- 节点可以被多个来源/频道引用，但权重、参与顺序和是否允许回退属于引用方，不属于节点。
- 后端提供统一出站策略解析与节点选择服务，前端共享一个策略编辑组件；维护入口分开不等于复制实现。

不再保留用户可见的“策略组 → 路由规则 → 来源数组”三层模型，也不在节点页保留另一套可编辑绑定入口。

## 2. 为什么要改

当前代码有 `proxy_nodes`、`proxy_groups`、`proxy_group_nodes` 和 `proxy_routes`；路由用 `source_ids_json` 关联来源，以 priority/id 确定第一个匹配项。

本地代码检查还发现：

1. `proxy_candidate` 实际使用 `ORDER BY weight DESC,n.id DESC LIMIT 1`，相当于总选权重最高的可用节点，并不是 UI 描述的按权重概率分配。
2. 实时搜索在找不到代理或策略读取报错时存在转为直连的路径；采集对“要求代理但没有节点”有不同处理，双方语义不一致。
3. 用户自定义频道可能继承第一个启用 TG 来源的策略，删改其他来源就可能改变它的出站行为。

这些是本次重构必须同时修正的执行语义，不能仅把表单移动到另一个页面。依据：`src/handlers/search.rs` 的 `proxy_candidate`、`crawl_routing_source`、`execute_source`，以及 `src/crawl.rs::fetch_page`。

## 3. 节点页只回答“有哪些线路、线路是否可用”

### 3.1 节点配置

- 节点名称、转发服务地址、启用状态、全局每日额度。
- 状态：正常、停用、额度耗尽、熔断、尚未验证。
- 运行信息：今日用量、最近成功/失败时间、最近错误摘要。
- 操作：新增、编辑、停用/启用、重置熔断；引用详情为只读。
- 不在本轮引入当前不支持的 SOCKS5/通用系统代理类型；继续沿用现有 HTTP 转发节点协议。

### 3.2 引用与安全边界

- 可以展示“被 N 个实时来源 / M 个 TG 频道引用”，点击抽屉查看名称并跳到所属对象编辑。
- 节点停用前提示影响范围；停用后保留引用，引用方显示节点不可用，不偷偷删除配置。
- 有引用的节点禁止物理删除，后端返回409及引用摘要；先解除引用再删除，不能通过外键级联静默改变策略。
- 修改节点地址或额度属于全局修改，影响所有引用者，需要展示影响范围。更换服务商推荐新建节点再逐个迁移。
- “直连”不是节点，不再以不可删除的系统节点混在节点库；它是策略的出站模式或显式故障回退。
- 重置熔断不等于验证可用；如增加探测能力，必须限定服务端允许的目标、计入请求预算，禁止任意URL探测。

## 4. 来源与频道中的策略编辑

在实时来源编辑器增加“出站策略”区域；TG 频道放在“采集与代理”页签。也可从列表行菜单“配置出站”打开专用弹窗，两者复用同一组件、接口和版本校验。

```text
出站方式    ( ) 直连  ( ) 使用代理
TG 频道可选 ( ) 继承 TG 默认策略

使用代理时：
  [选择节点]
  腾讯Edge      可用     权重 10     [移除]
  CF-1          可用     权重 20     [移除]
  CF-2          已停用   权重 20     [移除]

分配方式    [加权随机 / 按顺序故障转移]
没有可用代理节点时        [终止请求 / 允许直连]
代理已尝试失败后          [终止请求 / 允许直连]
最大代理尝试次数           [2]

摘要：优先通过代理访问；最多尝试2个不同节点；禁止直连回退。
```

- 新建实时来源必须明确确认出站方式；可以预选直连，但保存摘要不能隐藏这一事实。
- 代理模式至少配置一个节点、同一策略节点不重复、权重为正整数；不存在的节点拒绝保存。
- 既有停用节点保留并标红；暂时全不可用可保存为待修复配置，但运行必须失败关闭，不自动切直连。新建启用时给出阻断性确认/校验提示。
- 加权随机显示权重；顺序故障转移显示顺序，不用同一“权重”输入混淆两种语义。
- 使用单节点时隐藏多余分配控件，仍保留故障处理选项。
- 不把节点健康、全局额度、节点地址复制进策略表单作为可编辑字段。
- 配置保存成功不自动触发抓取、不自动重解析历史；实时来源的已有调试请求和采集任务均使用相同生效策略。
- 列表显示简短摘要，如“直连”“代理·3节点·禁止直连”“继承TG默认”；详情展示配置版本和实际生效内容。

## 5. TG 默认策略：处理自动创建频道

自动登记的用户自定义频道不适合逐个手动配置，需要明确的默认值，但不应该恢复一个全局策略管理中心。

- 在 TG 采集页的“采集设置”弹窗维护**唯一的 TG 默认出站策略**，使用同一策略组件。
- 新 TG 频道默认选择继承；管理员可给单个频道覆盖。
- 默认未配置时，不自动直连：显示“待配置出站策略”，可保存频道与任务，但调度不得发送网络请求，并返回明确阻塞原因。
- 默认策略调整前展示受影响频道数量；只有继承者受影响，独立配置不变。
- UI 同时显示“配置为继承”和展开后的“实际生效节点”，不是让用户猜。
- 默认策略是采集域配置，不属于节点库；未来若确需多个复用模板再单独设计，本轮不做命名策略组。

## 6. 执行语义

### 6.1 唯一规则

- 直连：直接访问目标，不进入节点选择。
- 代理：过滤停用、额度耗尽、熔断且未允许试探的节点，再执行已选分配方式。
- 加权随机：根据候选节点正权重随机选择，不是每次取最大权重。重试在未尝试节点中重新归一化，不重复同节点。
- 顺序故障转移：依明确顺序选择与重试，不能被节点ID排序覆盖。
- 无可用节点、尝试预算耗尽时，只有显式允许直连回退才可直连一次；不允许时返回可解释失败。
- 数据库/配置读取失败、配置缺失或损坏：直接失败，不能把异常吞掉当作直连配置。
- DSL错误、业务参数错误和非重试型上游响应不作为节点故障，不能用换代理掩盖解析问题；网络失败、代理服务失败及明确可重试状态按分类处理。
- 只读采集 GET 可按预算尝试；来源 POST 是否可重放必须明确声明安全，默认不自动重放，防止副作用重复。

### 6.2 配额、熔断与超时

- 节点额度全局共享，不能每个来源各记一份。每次实际发出的代理请求（包括重试）计一次，直连单独统计。
- 节点配额领取与半开探测锁必须原子化，避免并发搜索/worker超额；数据库错误不能绕过预算。
- 一次搜索来源执行或采集页处理有总时限，节点尝试次数和单次时限不得相乘后突破总预算；不在本轮策略表单中重复添加全局安全限制。
- 一个逻辑请求开始时取策略版本快照，节点停用/额度/健康在每次发请求前重新检查；不能在请求一半时因默认策略变化改为直连。
- worker 按页重新读取生效策略，不因运行数小时的回填任务固定旧策略；重试也要遵守新启停状态与剩余预算。
- 保留现有出站目标/DNS/重定向/请求头安全校验，策略编辑不能绕过安全边界。

### 6.3 可观测性

记录所属来源/频道、策略版本、实际节点、每次尝试、状态、耗时和回退原因；租约、令牌、敏感请求头不得返回前端。

`/api/search` 和 `/api/search/json` 仍沿用现有 `proxyNodes` 等公共统计字段，不因后台重构增加不必要的公共字段。TG 本地查询没有代理访问，采集节点信息展示在采集任务中，不能伪造搜索阶段走代理。

## 7. 数据模型与管理接口（目标设计）

### 7.1 模型

继续保留 `proxy_nodes`，用所属对象策略代替组/路由：

- `outbound_policies`：模式、分配方式、故障处理、尝试预算、版本、更新时间及唯一所属对象。
- 所属对象使用明确外键（实时 source_id、channel_id、TG默认配置键三选一）和 CHECK 约束，不能只用无外键的字符串 owner_type/owner_id 留下孤儿。
- 每个实时来源最多一份策略、每个频道最多一份独立策略、TG默认仅一份；频道“继承”由显式模式表达，不以缺行推断成直连。
- `outbound_policy_nodes`：policy_id、node_id、weight、position；唯一(policy_id,node_id)，节点外键采用限制删除。
- 策略及成员同事务保存，expectedVersion 乐观锁防止两处弹窗覆盖；节点状态/用量仍是运行时共享状态。

策略所有权字段为服务端控制，不能通过编辑JSON把自己的策略改挂到别的实体。

### 7.2 API职责

- 节点 CRUD / 状态接口继续位于现有管理员代理域，节点列表不再返回策略组与来源目录的大杂烩。
- 新增节点引用查询，只读且管理员可访问。
- 来源、频道各自提供读取/保存出站策略子接口；TG默认策略接口位于采集设置域。复用同一服务、DTO与校验器。
- 完整来源/频道保存与策略保存必须明确事务边界；一个编辑器点击一次保存时，要么所有部分成功，要么都不变，不能先保存基本信息再让策略失败却提示整体成功。
- 节点删除并发与新绑定并发由外键/事务兜底，不仅依赖前端“引用数为0”。
- TG旧来源ID仅保留搜索身份，不能再通过来源策略接口写一份与频道配置冲突的策略。

## 8. 迁移

1. 导出节点、组、路由、有效优先级、来源/频道映射、fallback、额度和健康状态。
2. 按当前规则计算每个来源实际命中的路由；共享组展开为各来源独立策略，对节点仅保留引用，不复制节点。
3. 无命中路由的既有来源若实际直连，显式迁移为直连并列入确认报告；不把它默认为新代理模式。
4. 同频道多个来源映射不同节点、权重或回退规则时，报告冲突，管理员确认后才归并。
5. 旧“直连节点”若严格低于所有代理，精确迁为 unavailableFallback=direct，原 fallback 决定尝试失败回退；若高于或等于部分代理则阻断迁移并人工确认。迁移后删除伪节点。
6. 旧 weight 实际表现为优先级：默认按当前 weight降序、ID降序迁移为显式故障转移顺序，保留当前首选节点，并先保持一次代理尝试；若选择加权随机必须明确确认，这是行为变更，不是无损迁移。
7. 旧用户频道的隐式继承展开成可审计映射；需要一个TG默认策略时管理员明确选定。无法无歧义映射的频道保持独立配置，不能统一覆盖。
8. 保留节点ID、额度、熔断等状态；事务切换策略读取，失效配置缓存；worker按检查点安全切换。
9. 验证来源与频道生效策略一致后移除旧 group/route 表、接口和页面代码，不长期保留双写适配层。

历史上“代理不可用意外直连”的行为不作为必须保留的兼容功能；迁移报告列明并按新的显式故障处理修正。

## 9. 开发与验收

- 前端抽取 `OutboundPolicyEditor`、节点多选和策略摘要，实时来源、TG频道、TG默认复用；节点页只保留节点表单和引用抽屉。
- Rust 抽取独立出站策略服务供实时搜索、来源调试、采集worker共用，不让worker继续依赖搜索handler里的私有策略函数。
- 删掉旧“新增策略”“绑定资源源”“全局路由优先级”入口及对应死代码。
- 测试包含：加权分配的确定性随机源测试、顺序回退、无节点/配置失败不直连、显式直连回退、POST重放边界、配额并发、半开探测、停用影响、引用删除冲突、乐观锁、默认继承和独立覆盖、迁移混合直连节点冲突。
- 端到端验证同一套策略分别用于实时来源与TG抓取；TG本地搜索不产生外部代理请求。
- UI 验证三处编辑器一致，节点页不出现策略编辑；错误就地显示、保存不丢稿、弹层不堆叠。

本设计与 `docs/tg-crawl-workbench-design.md` 一起实施；公共首页、搜索授权与接口结构不变。
