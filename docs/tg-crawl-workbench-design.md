# TG 采集工作台重构：设计与开发方案

> 2026-09-30：本轮核心范围已实施。本文保留需求设计背景；实际组件、接口、迁移和验收差异以 `tg-workbench-implementation.md` 为准。直连回退拆分为无可用节点 / 尝试失败两类，末位直连伪节点可精确自动迁移。

- 日期：2026-09-30
- 状态：本轮核心功能已实施并完成本机迁移；验收与范围说明见实施记录。
- 范围：后台 `/admin/sources`、`/admin/crawl` 及必要的采集管理接口、配置读写与数据迁移。
- 技术基础：Vue 3 SPA、shadcn-vue / Reka UI、Rust、PostgreSQL、Redis。项目当前不是 MySQL。
- 不变项：首页搜索 UI、公共 SearchResult、`/api/search` 的 SSE 契约、`/api/search/json` 的结果与统计结构。

## 1. 结论

**把 TG 频道的日常维护完整迁到「TG 采集」，来源管理只维护实时 HTTP 来源。**

这不是将两个表格换位置，而是明确两类资源获取方式的边界：

| 入口 | 管什么 | 不再做什么 |
| --- | --- | --- |
| 来源管理 | 实时来源的请求、DSL、启用、调试 | 不再新增或编辑 TG 频道 |
| TG 采集 | 频道配置、采集调度、任务、消息、解析复核、搜索发布 | 不编辑任意 HTTP 方法、请求体或带搜索词的 TG URL |
| 代理节点 | 节点配置、可用状态、全局额度、只读引用 | 不定义策略，不挂载来源或频道 |
| 网盘资源 | 入库资源的查询与管理 | 不承担消息、采集任务排障 |

保留 `/admin/sources` 和 `/admin/crawl` 路径，侧栏名称仍为「来源管理」「TG 采集」。不增加重复导航，不恢复此前删除的大标题/说明区域。

**保留数据身份，不保留双维护入口。** 原 TG 来源 ID 仍用于搜索身份和既有引用；采集配置只有一个写入入口。迁移后旧管理接口不能继续绕过新入口修改 TG 配置。

## 2. 代码核查得到的现状

以下为当前实现，不是待开发能力：

1. `src/handlers/search.rs` 的 `source_execution_stream` 按 TG URL 将来源分流，本地 TG 查询与非 TG 实时搜索合并输出；TG 已不逐个联网搜索。
2. `src/local_index.rs` 使用来源 ID / URL 确定频道范围及 Redis 缓存身份，结果统计仍映射回原来源 ID、名称和优先级。
3. `src/crawl.rs::discover` 从 `resource_sources` 和用户自定义频道发现采集频道。worker 启动、周期扫描以及频道列表 GET 都可能触发发现；目前“查看列表”并非纯读取。
4. `source_for` 从同频道来源中按启用、优先级、ID 选取一个配置，拿到 DSL；没有来源记录时使用频道模板。多个来源的 DSL 冲突目前依赖隐式排序处理。
5. 抓取代理仍通过来源 ID 选择策略；用户专属频道还可能继承第一个可用 TG 来源路由。不能直接删掉 TG 来源行。
6. 自动调度依赖频道启用状态，以及启用的来源绑定或 `requested_until`。采集开关和搜索来源开关存在耦合。
7. 当前 `frontend/pages/admin/crawl.vue` 把频道表、最近 50 条消息、预览 JSON / HTML、最近任务依次铺在同一页面；查看消息和预览只是设置变量显示 Card，没有弹层。
8. 所有操作共用一个 `busy`，所有频道共用页面顶部的 `maxPages`；编辑间隔直接在表格里完成。后台轮询混在页面内，需要额外维护脏字段。
9. 消息列表固定 50 条；任务接口只有频道和 limit 筛选，没有正式分页、状态筛选和单任务详情接口。部分接口直接返回数据库 JSON，字段存在 snake_case / camelCase 混用。
10. 消息预览只调用 transform，实际入库还有时间覆盖、复核判定、去重与资源关系处理。预览不能直接冒充“当前已入库结果”。
11. 来源相关的全量保存、启用配置、导入导出同样需要检查：只在前端隐藏 TG 行，可能导致保存可见行时把隐藏 TG 来源停用或覆盖。

代码依据：

- `frontend/pages/admin/crawl.vue`
- `frontend/pages/admin/[...view].vue`
- `frontend/components/admin/navigation.ts`
- `src/handlers/crawling.rs`、`src/handlers/settings.rs`
- `src/crawl.rs`、`src/handlers/search.rs`、`src/local_index.rs`
- `src/queries/telegram_search.sql`
- `migrations/003_telegram_index.sql` 至 `005_crawl_single_channel.sql`

## 3. 目标与非目标

### 3.1 本轮必须解决

- 无需返回来源管理即可完成新增频道、配置解析/代理、启动任务、查看消息、定位失败。
- 页面主内容不因打开消息或任务详情而不断增高。
- 日常管理和排障入口同级，任务不再被埋在页面最底部。
- 清楚区分“允许采集”“当前正在执行”“资源参与公共搜索”，不能把 enabled 直接显示成“采集中”。
- 配置保存、排队成功、任务完成三种结果明确区分。
- 读取、预览、保存、重解析有明确边界；预览绝不写资源。
- 保留已有频道、资源、原文、任务进度、代理绑定与用户可见范围。

### 3.2 不包含

- 不改首页；不改变非 TG 实时搜索方式。
- 不实现私有频道、登录绕过、Telegram 全历史保证或网盘下载。
- 不做“删除频道时清空所有资源”的快捷按钮。
- 不引入新的前端状态库、独立消息库或第二套代理系统。
- 不把此次 UI 重构扩展成采集引擎整体重写。

## 4. 信息架构与页面布局

```text
顶栏：管理后台 / TG 采集

紧凑状态条：Worker 在线/离线/未知 · 排队 N · 执行 N · 失败 N · 待复核 N
                                            [刷新] [新增频道]

[频道]  [任务（活动数）]  [待复核（消息数）]
────────────────────────────────────────────
当前页签筛选栏
当前页签表格 / 加载态 / 空态 / 错误态
分页
```

- 同一时刻只渲染当前页签主列表，不在频道表下附加任务表或消息表。
- 状态条只放可操作的关键指标；大段部署说明收进“运行说明”帮助弹窗。
- 数字为当前权限下全局统计，列表数量为当前筛选结果，文案必须区分。
- URL 保存页签、筛选和分页，例如 `/admin/crawl?tab=jobs&channel=xxx&status=failed`。
- 浏览器返回恢复列表筛选、页码和滚动位置。深链参数非法或对象已删除时显示就近错误并可返回列表。

### 4.1 频道页签

筛选：频道名称 / username、采集开关、公共搜索发布状态、运行异常、来源类别（管理员维护 / 用户请求）。

建议列：

| 列 | 内容 |
| --- | --- |
| 频道 | 显示名、@username、来源类别 |
| 采集 / 搜索 | “允许采集/已暂停”；“已发布/未发布”；用户请求标记 |
| 数据 | 消息数、有效资源数、待复核数；点击消息/复核数进入对应视图 |
| 同步 | 最近成功同步、下次计划时间、历史覆盖摘要 |
| 当前任务 | 排队/执行/暂停摘要；没有活动任务时展示最近结果 |
| 操作 | 查看消息、立即同步；其余放行操作菜单 |

- 表格不直接放可编辑间隔、完整错误、完整任务计数和所有操作按钮。
- 错误只展示摘要，完整错误与节点诊断放详情。
- “允许采集”不代表 worker 在线，也不代表此刻正在抓取。
- 名称过长截断并可查看完整值；窄屏仅表格局部横向滚动，操作列可访问。

### 4.2 任务页签

- 顶层页签直接可达，默认查看活动任务；可切换全部、失败、已完成。
- 筛选：频道、类型（同步/历史回填/近期复查/重解析）、状态、创建时间范围。
- 列：任务 ID、频道、类型、状态、已处理页数/消息数、创建/更新时间、结果摘要、操作。
- 点击任务 ID 打开任务详情抽屉。
- 排队、执行中、暂停允许取消；失败允许重试；最终许可仍由后端校验。
- 取消当前任务不等于暂停频道，自动调度可能产生后续任务；确认文案必须说明这一点。
- 不展示虚构完成百分比。页数上限是任务预算，不是频道总页数；资源计数明确标为“资源写入次数”，不能当作新增唯一资源数量。

### 4.3 待复核页签

- 聚合 `failed` 和 `review` 消息，分别显示解析失败与需要人工复核，不混成任务失败。
- 筛选：频道、问题类型、消息时间；支持分页。
- 行内展示消息摘要、原因、发布时间、解析版本；打开消息详情进行定位。
- 当前引擎没有人工批准聚合消息的能力，本轮不做无效的“通过审核”按钮。
- 路径是：查看原因 → 调整 DSL → 只读预览 → 显式重解析 → 刷新实际状态。
- 单条重解析作为本轮新增能力；不得用“重解析整频道”冒充单条修复。

## 5. 弹层与主要交互

### 5.1 新增 / 编辑频道：右侧 Sheet

页签：基本设置、采集与代理、解析规则。

- 基本设置：username 或公开 URL、显示名、备注、公共搜索发布状态；用户请求频道显著标注其可见范围。
- 采集与代理：允许采集、同步间隔、频道自有出站策略（选节点、分配/回退）或继承 TG 默认策略，以及实际生效信息。
- 解析规则：继承默认模板 / 频道独立 Rust transform DSL；显示模板/配置版本，提供样本预览。
- 不再展示 HTTP 方法、响应格式、任意目标 URL 和 keyword 模板等不适用于 TG 的配置。
- username 在已有消息后不可直接改名复用历史；更换频道须新建，避免混合历史身份。
- 新建频道初始为未发布、暂停，保存后可明确选择“启动首次同步”；排队成功不宣称采集成功。
- 暂停只影响后续采集及已有任务租约，不自动隐藏已入库搜索结果。
- 取消公共发布只移除公共目录绑定，不清除资源；用户自己的合法频道绑定仍独立生效。
- 底部固定取消/保存，错误就地显示，失败保留输入；提交期间阻止重复提交及意外关闭。
- 有未保存修改时关闭/离开需确认；不能只靠禁止遮罩点击防止丢稿。

### 5.2 查看消息：消息浏览 Sheet

```text
@channel 的消息                         [关闭]
[解析状态] [消息时间] [查询]
消息 ID | 摘要 | 发布时间 | 状态 | 资源数 | 查看
…
分页
```

- 点击“查看消息”立刻打开抽屉并显示骨架屏，不跳到页面底部。
- 固定标题和分页，列表区域独立滚动；默认按消息 ID 倒序，支持服务器端游标分页。
- 点击消息进入**同一抽屉的详情视图**，顶部提供“返回消息列表”。不再开第二层大抽屉，不向抽屉尾部追加原文。
- 返回时保留筛选、游标和滚动位置。直接从待复核打开时，返回对应待复核列表。
- 任意时刻最多一个主业务 Dialog/Sheet；只允许短确认框作为附属弹层。

### 5.3 消息详情

顶部显示频道、消息 ID、发布时间、解析状态、当前入库版本。

详情页签：

1. **已存资源**：来自该消息 occurrence 的现有结果；用资源卡展示名称、描述、网盘类型、链接、提取码、资源时间；另标识资源是否被人工覆盖/停用，不把全局资源状态和消息原始结果混为一谈。
2. **当前规则预览**：点击后执行只读解析，显示当前配置版本、结果及复核原因；明确“尚未写入”。先卡片，JSON 作为可折叠的技术视图。
3. **消息原文**：默认纯文本；原始 HTML 以转义代码显示，支持复制，不使用 `v-html` 执行。

- 链接独立显示，不混进名称、描述；预览和持久化共用 Rust 解析/清洗/时间与复核判定路径。
- 修改 DSL 后旧预览标记失效，必须重新预览，不能让旧结果误导保存。
- “重解析此消息”独立确认并排队；只显示请求已接收，完成后重新读取实际资源和状态。
- 原文、SQL 内部字段和完整诊断按需加载，不塞进每一行列表接口。

### 5.4 启动任务：紧凑 Dialog

展示频道、任务类型、该类型的说明与适用参数。删除页面顶部跨频道共用的 maxPages。

- 同步/回填/近期复查使用“最多抓取页数”。
- 重解析使用已有原文的批次/消息预算，不把数据库批次称为 Telegram 页数。
- 历史回填明确“从保存的检查点继续”，不是承诺全历史。
- 同类活动任务冲突返回 409，提供“查看已有任务”，不能只弹出报错。
- 提交成功提示“已排队”，提供打开任务详情；worker 离线时仍可排队，但明确不会立即执行。

### 5.5 任务详情：独立 Sheet

- 展示状态、时间、检查点、计数、终止原因、当前/最近节点、错误与重试信息。
- 诊断只展示现有可证实字段；没有逐页历史日志时不能伪造任务时间线。
- 页签或分段组织概览和技术诊断，长 JSON 默认折叠。
- 根据任务状态显示取消或重试，操作返回后刷新当前详情与列表，不重置列表筛选。

## 6. 数据职责与迁移方案

### 6.1 目标所有权

- `crawl_channels`：频道采集配置的唯一权威记录，包含启用、间隔、显示信息、解析模板模式/独立 DSL、配置版本、归档状态及采集代理目标。
- `resource_sources`：保留公共搜索来源身份、名称、优先级、发布状态及频道引用；增加显式 `kind`（live / telegram），不再在业务写入时仅猜 URL。
- TG 对应来源行不再是 DSL/采集代理配置的独立写入点；worker 从频道读取配置。
- `source_messages`、`resource_occurrences`、`managed_resources`、`crawl_jobs` 继续复用，不复制到第二套表。
- 用户自定义频道绑定继续独立维护；用户请求频道不能仅因被采集就进入公共搜索。
- 同一频道只采集一份，可有多个历史搜索身份；多个来源 ID 不意味着多跑一次采集。

频道“公共发布”通过对应公共来源绑定保存，不能再加一个不同步的布尔字段。历史多个身份时，在高级绑定区列出并明确每项发布状态；默认操作作用于选中的绑定，禁止不提示就批量启停。

### 6.2 节点库与业务出站策略分离（修订）

采用用户提出的归属方式：节点页只管节点；实时来源、TG频道各自维护出站策略，不再选择节点页创建的共享策略组。

- `/admin/proxies` 只维护节点地址、启停、全局额度与健康状态；引用信息只读，修改绑定跳到所属来源/频道。
- 实时来源和TG频道分别选择节点、设置权重或故障转移顺序、是否允许直连回退；同一节点在不同业务对象上可以有不同权重。
- TG采集设置仅保留一个明确的默认出站策略，供自动登记的用户频道继承；频道可覆盖。默认未配置时不偷偷直连。
- 直连是访问模式，不再伪装成节点；无可用代理仅在明确允许回退时直连。
- 前端共用策略编辑组件，后端共用出站服务；同频道多个来源的历史绑定冲突在迁移前确认。
- 当前weight实现实际是最高权重优先，并非概率分配；迁移不能把更改算法称为无损迁移。
- 移除旧共享组/路由的多级间接绑定和双入口，不保留长期兼容层。

数据模型、执行语义、配额/熔断、节点删除约束与迁移详见 `docs/outbound-policy-ownership-design.md`，以该文档为代理重构的补充规范。

### 6.3 迁移步骤

1. 只读预检：统计 TG 来源、频道、用户绑定、任务、消息、occurrence、资源，导出来源→频道→DSL→代理→发布状态映射。
2. 检查重复频道、无法规范化的 URL、不同 DSL/代理绑定、孤立配置，输出冲突清单。
3. 备份数据库与配置；先解决冲突再切换。不得因“无需兼容”直接删数据。
4. 停止 worker 领取新任务，等待执行到检查点或让租约安全失效；迁移期间暂停后台相关配置写入。
5. 数据迁移添加显式分类和频道配置，保留原来源 ID、消息主键、资源 ID、任务 ID、检查点、手工覆盖、删除标记及用户范围。
6. 同一频道 DSL/代理一致时自动归并；不一致必须先由管理员选择/合并配置。不存在明确决策就中止切换，不用排序规则替用户决定。
7. 原子切换管理入口、worker 配置读取、调度条件、代理目标和搜索目录读取；迁移只执行一次，允许失败重跑而不重复插入。
8. 重建必要索引，推进配置/本地索引 revision，使旧 Redis 缓存自然失效；不使用 FLUSHALL。
9. 核对计数与映射、启动 worker、验证搜索与代理。移除旧发现写入路径与 TG 旧配置写入口，不长期双写。

回滚依靠迁移前备份和版本化发布，先停 worker 再处理；若切换后已产生新数据，先导出并制定补偿，禁止直接覆盖备份造成新增数据丢失。

### 6.4 必须一起解耦的逻辑

- `GET /crawl/channels` 改成纯读取，禁止触发配置发现写入。
- 自动调度由采集启用与有效采集需求决定：管理员维护频道不再受公共发布开关控制；用户请求频道继续遵守有效请求期限。
- 新用户请求频道在注册服务中幂等建立/续期；不能把周期性全表发现当成长期配置同步机制。
- 来源管理的删除、导入导出、启停、批量保存只操作 live 范围。系统设置中的公共搜索来源选择显式包含两类身份，不能把“来源管理可见行”当完整目录。
- 频道归档不硬删历史消息；有活动任务时需处理任务与租约，有用户有效绑定时不能用公共取消发布冒充彻底删除。
- DSL 变化不自动重写所有历史资源；提示需要重解析，管理员显式启动任务。

## 7. 后端接口计划（待开发）

沿用管理员鉴权、现有成功/失败响应外壳。新增管理 DTO 使用 camelCase，禁止直接 `to_jsonb(row)` 透出数据库字段；前后端同步升级，不维护两套后台协议。公共搜索协议保持原样。

| 接口 | 计划 |
| --- | --- |
| `GET /api/admin/crawl/overview` | 新增全局计数、worker 心跳状态、服务端时间 |
| `GET /api/admin/crawl/channels` | 纯查询；q、enabled、published、origin、异常筛选；分页 |
| `POST /api/admin/crawl/channels` | 新增公开频道、配置校验与重复冲突处理 |
| `GET /api/admin/crawl/channels/{channel}` | 完整配置、生效解析/代理及绑定详情 |
| `PUT /api/admin/crawl/channels/{channel}` | 完整编辑，携带 expectedVersion 防止覆盖并发修改 |
| `POST /api/admin/crawl/channels/{channel}/archive` | 归档入口；本轮不提供物理删除 |
| `POST /api/admin/crawl/channels/{channel}/jobs` | 复用排队能力，按任务类型校验参数并返回任务摘要 |
| `GET /api/admin/crawl/jobs` | 频道/类型/状态/时间筛选，稳定游标分页 |
| `GET /api/admin/crawl/jobs/{id}` | 新增单任务详情，脱敏诊断，不返回租约 token |
| `POST /api/admin/crawl/jobs/{id}/cancel`、`retry` | 复用，补冲突状态和关联任务信息 |
| `GET /api/admin/crawl/channels/{channel}/messages` | 状态/时间筛选，游标分页，摘要，不带原始 HTML |
| `GET /api/admin/crawl/channels/{channel}/messages/{id}` | 已存详情、原文按需加载；不自动执行当前 DSL |
| `POST /api/admin/crawl/channels/{channel}/messages/{id}/preview` | 只读 DSL 预览；可传未保存 DSL，限大小、超时、并发 |
| `POST /api/admin/crawl/channels/{channel}/messages/{id}/reparse` | 新增单条重解析排队，使用版本校验 |
| `GET /api/admin/crawl/review` | 跨频道 failed/review 消息查询与分页 |

分页约定：频道使用 page/pageSize（默认20，上限100）；持续写入的任务和消息使用不透明 cursor，响应 `items`、`nextCursor`、`hasMore`。任务以 ID 为稳定顺序，跨频道复核采用时间+频道+消息 ID 的稳定组合；筛选变化重置 cursor。消息页显示上一批/下一批，不伪造总页数。

- 时间过滤采用明确含时区的 RFC3339 参数；后台时间返回 UTC，统一由展示层格式化并标明当前时区，null 为“—”。公共资源 datetime 保持既有格式和约定。
- 单条重解析任务需要独立目标消息字段/任务类型，更新 SQL CHECK、同类活动唯一约束、worker 分派与取消逻辑；继续保证同频道最多一个执行任务，不能复用整频道 reparse 而忽略 messageId。
- 并发提交使用频道锁、已有活动任务约束和幂等请求标识共同控制；前端按钮禁用不是唯一防线。
- Worker 在线状态新增心跳：Redis 带 TTL、可识别多个 worker；Redis 不可用显示“未知”，不能错误断言离线。心跳只代表进程活性，任务进展另看任务更新时间。
- 所有写接口继续执行既有管理员权限与请求来源校验；预览虽不落库，仍要限制成本。

### 7.1 查询成本与一致性

- 列表只取摘要，完整 DSL、原文和诊断在详情中加载；频道列表不能每次轮询都按每个频道重新全表统计消息/资源。
- 先用 EXPLAIN ANALYZE 验证查询；为消息状态+频道+消息 ID、任务频道/状态+ID、跨频道复核排序增加匹配索引。索引按实际查询规划添加，不盲目堆叠。
- 状态条计数允许短时缓存并返回统计时间；任务状态从 PostgreSQL 读取，Redis 不作为持久进度的权威来源。
- 新增单条重解析目标后，资源、消息状态与索引 revision 在同一事务提交；预览不获取长时间写锁。
- 初始心跳建议每10秒发送、45秒TTL；新环境无心跳显示“未检测到 worker”，Redis读取失败显示“状态未知”，不把两者混为一谈。
- 标准化 ID、URL 和查询参数由后端验证；未保存 DSL 的执行必须受现有 Rust DSL 能力与资源限制约束，不允许任意脚本或任意外部请求。

## 8. 解析一致性

从采集持久化中抽取纯解析服务，供 worker 和预览共享：

```text
已存消息原文 + 消息发布时间 + 解析配置/版本
  → Rust transform DSL
  → 资源归一化（标题/描述/链接/类型/标签）
  → 时间规范化 + 聚合消息复核判定
  → 结构化解析结果 / 错误
       ├─ 预览：只返回，不写库、不改检查点、不递增索引 revision
       └─ 入库：事务维护 occurrence、资源身份/覆盖保护、进度、revision
```

预览只保证解析输出一致，不能声称已完成真实入库的去重、人工覆盖合并与事务提交。UI 要明确区分“解析结果”“消息已存结果”“最终可搜索资源”。

验收：名称/描述不包含 HTML 和网盘 URL，链接保留必要的分享 fragment 与提取码，消息发布时间不是采集执行时间；无时间不造假。测试复用当前 SearchResult 与来源清洗样本，不实现前端第二套解析器。

## 9. 前端实现划分与状态管理

建议目录（均为待创建/调整）：

```text
frontend/pages/admin/crawl.vue                 # 页签与 URL 编排，不能再承包所有业务
frontend/components/admin/crawl/
  CrawlOverview.vue                           # 状态条
  CrawlChannelsTab.vue / CrawlJobsTab.vue / CrawlReviewTab.vue
  CrawlChannelEditor.vue                      # 频道配置 Sheet
  CrawlMessagesSheet.vue                      # 消息列表与详情视图容器
  CrawlMessageDetail.vue                      # 已存结果、预览、原文
  CrawlJobDialog.vue / CrawlJobDetail.vue      # 启动任务 / 任务详情
  CrawlResourcePreview.vue                    # 后台结构化资源预览
frontend/composables/admin/useCrawl*.ts        # 分领域查询与操作，不造通用框架
frontend/types/crawl.ts                       # 明确 DTO，去除页面 any
```

复用 AdminDialog、AdminConfirmDialog、AdminRowActions、AdminSelect、Table、Tabs、Badge、Button，不再写一套遮罩、焦点陷阱或滚动锁。只在后台封装需要的预览，避免改公共 ResourceDescription 影响首页。

状态约束：

- 列表 loading/error、详情 loading/error、每个写操作 pending 独立，不能一个 busy 锁整个工作台。
- 仅当前页签和打开的详情轮询；详情活跃时建议5秒、列表15秒、后台隐藏时暂停，失败后退避；卸载清理。
- 请求切换使用 AbortController 或请求序号，频道 A 的迟到响应不能覆盖频道 B。
- 刷新列表只更新服务端快照，不覆盖编辑草稿；保存成功按对象 ID 更新列表，再后台校准。
- 鉴权失效停止轮询并使用已有登录门禁；一般失败保留上次数据，显示更新时间和重试，不把列表清空成“无数据”。
- 表单字段标注范围和单位，保存失败有字段/表单错误；提交成功有明确提示，不在每次自动刷新时弹 toast。

## 10. 视觉、可访问性与响应式规范

- 沿用 shadcn neutral：统一边框、圆角、间距、输入框、页签和按钮层级；不加渐变大横幅。
- 主操作少而明确；危险操作不与“查看”并排铺满每行。
- 宽屏消息 Sheet 建议 880～1040px，普通编辑 640～760px；最终受视口约束。小屏全宽，标题与底部操作固定，只有内容区滚动。
- 原文/JSON 必须在自身代码区域换行或局部横向滚动，不撑宽抽屉；不默认展开数千行。
- Dialog/Sheet 唯一标题和关闭按钮；支持键盘、Esc、焦点恢复、加载播报与 `role=alert`。
- 状态不能只靠颜色；危险确认默认聚焦取消；表格操作提供可访问名称。
- 验收覆盖1280×720、1280×480、390×844、320×740；不允许页面级横向溢出。

## 11. 开发顺序与交付门槛

### P0：数据与契约确认

输出迁移预检、配置冲突清单、DTO、当前公共搜索契约基线。确认频道所有权、发布范围、代理映射和回滚步骤；不满足不得切数据。

### P1：先修工作台交互

将当前功能拆成频道/任务/待复核页签与共享弹层，移除底部消息/预览/最近任务堆叠；同步补分页和详情接口、独立 loading/error、请求竞态保护。不隐藏尚无替代入口的 TG 编辑能力，避免中间版本无法维护。

### P2：频道维护迁移

实现频道 CRUD/版本控制、显式来源分类、代理频道目标、配置迁移和纯读取 GET；切换 worker 配置与调度；来源管理移除 TG 编辑。只保留一个权威写入口。

### P3：解析复核闭环

共享纯解析服务、已存与预览分离、单消息重解析、任务心跳/诊断、发布与缓存失效。完成自动化与浏览器回归后交付。

P1 可以作为 UX 独立阶段验收，但完整交付必须包含 P2/P3；不能仅换样式就宣称完成频道维护迁移。

## 12. 验收清单

### 交互

- [ ] 从频道行查看消息，主页面高度、滚动位置不变；详情不往下追加。
- [ ] 消息详情返回列表时筛选、游标和滚动位置保留；关闭恢复触发控件焦点。
- [ ] 任务入口始终在顶部页签，支持筛选、分页、独立详情。
- [ ] 新增/编辑/任务弹窗在窄屏及低高度下可操作，保存按钮不被挤出视口。
- [ ] 保存失败不丢稿；重复点击不产生重复任务；401/403 停止轮询。
- [ ] 切换频道期间迟到响应不串数据，后台轮询不覆盖编辑。
- [ ] 空列表、无筛选结果、无可访问原文、解析失败、worker未知/离线均有明确状态。

### 后端与数据

- [ ] GET 无配置写入；管理员权限、来源校验、分页边界和非法参数有契约测试。
- [ ] 暂停采集不下架资源；取消公共发布不泄露或误删用户频道绑定。
- [ ] 同频道多来源配置冲突阻止静默迁移；旧 ID、关系、检查点、人工覆盖和删除标记保留。
- [ ] 来源管理全量保存/导入导出不会改写隐藏 TG 项；公共搜索范围不意外扩大或缩小。
- [ ] 指定代理仍命中对应策略，无代理可用不静默直连；用户频道默认路由显式可解释。
- [ ] 预览无写入；预览/重解析/采集使用同一清洗与时间逻辑；单条重解析不变成全频道任务。
- [ ] 活动任务唯一性、暂停/取消与租约竞争、worker重启续跑、幂等重试有数据库集成测试。
- [ ] 迁移前后计数、关联、发布范围和搜索 fixture 对比一致；Redis 失效采用版本，不清空实例。
- [ ] `/api/search` 与 `/api/search/json` 的字段、统计、来源身份及非 TG 流式行为不回归。

### 验证方式

单元与契约测试、隔离 PostgreSQL/Redis 集成测试、前端 typecheck/test/build、生产构建浏览器验收分别记录。真实环境仅做只读验收；创建、重解析、取消和归档测试使用隔离测试频道/数据库，不拿真实资源做破坏性验证。
