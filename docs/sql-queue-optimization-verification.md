日期：2026-10-02。按开发环境直接修改，不保留旧调度排序，不构建/打包 Release。

## 本轮已经修改

- 迁移 018：检查队列存储 provider/到期时间，并由触发器同步目录延期。优先级固定为 10（用户点击）、1（采集）、0（周期补队）。同优先级按到期时间、ID 排队，不再跨表按最近出现时间排序。
- 认领按两个 provider、三个优先级分别走复合索引；每个分组最多锁一个候选，最终只认领全局最优一个。使用 SKIP LOCKED；语句结束后其他候选锁释放。未到期的高优先级和无可用账号的 provider 不阻塞到期任务。
- 补队使用数据库持久化的 provider 游标。每轮每个 provider 最多检查 256 个到期目录条目，先排除已有活动任务，再 INSERT；遍历到尾部回绕。游标/入队同一语句提交，重启不丢进度，冲突不会永久挡住后面的条目。一次全队列覆盖仍需要多轮，不是立即补齐所有历史链接。
- 查询中的 LIMIT 放在 LATERAL 内部，使目录 B-tree 能从游标直接读取小批次；初稿 LIMIT 位于关联外侧，实测仍扫描全表，已修正。
- 检查关闭时，采集不再产生休眠检查任务；以后开启时通过上述游标补偿。已有历史 queued 不删除。点击可按需创建/提升到优先级 10，不抢占正在运行的租约。
- 过期 running 租约每轮恢复最多 100 条，重新读取目录到期时间。认领后复核目录是否到期，以处理入队快照与前台检测的竞态。
- 后台检测结果/限额延期落库前锁定并验证当前租约，包含实际时钟的到期检查；旧 token 或过期 worker 不得覆盖当前检测结果。完成更新也校验 token/status。
- 按原有规则清理过期取链请求和完成超过七天的检查任务；每张表每轮最多删除 1000 条，按索引排序并跳过锁住的记录。不新增原文、日志或云盘操作的保留期限。
- 删除 `idx_managed_resources_search_trgm`、`idx_resource_tg_name`、`idx_resource_tg_date`，原合计约 263MiB；保留后台名称 GIN、两个不同键顺序的 gram 索引和 fingerprint 唯一约束。删除旧检查调度索引，改为 queued 认领与 running 租约部分索引。索引数据可由原表重建，业务行未删除。

## 仍有价值，但本轮没有伪装成已经解决的项

1. 全局采集提交锁仍在；可以把更多解析/规范化移出事务，合并每页资源刷新，再按频道拆分失效版本。需要并发锁顺序与跨频道资源共享验证。
2. 资源页深 OFFSET 仍随页数增长；下一步可同时改 API/前端为稳定游标分页，不必保留旧页码接口。
3. 消息列表当前读取 raw_html 并解析摘要；可在采集时持久化纯文本摘要，列表不再取原文。消息详情/重解析仍需原文。
4. 大量原文已由 PostgreSQL TOAST 独立存储。另建原文表本身不自动节约空间；真正归档应包含压缩/存储目标与读回重解析机制。尚未规定原文/操作历史的保留期限，因此不自动删原文、也不把云盘操作四分钟租约误当成可删除的幂等历史期限。
5. `pg_stat_statements` 与慢查询基线仍值得配置，但需要数据库加载/重启安排和正确的数据卷，不能为了观测盲目重建容器。
