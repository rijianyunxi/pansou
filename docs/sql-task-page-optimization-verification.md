# 检查任务查询与索引整理验证

日期：2026-10-03。范围：检查任务页面、同步队列索引整理、消息倒序索引去重。

## 实现与数据库状态

- `src/handlers/tasks.rs` 按实际筛选条件绑定参数。无网盘筛选的计数不关联 `link_catalog`；有网盘筛选时仍以目录的 `provider` 为准，因为历史/运行中/转存链接任务的队列快照可能过期。
- “需要关注”拆成失败任务、租约到期的运行任务、关联失败链接的任务三个候选分支，以 `UNION` 去重。涵盖 original/reshared、无 error_code 的失败链接、空租约排除规则。
- 先按 `created_at DESC,id DESC` 在窄候选上筛选、分页，再通过 `MATERIALIZED` 页集合读取任务/链接详情。精确总数、原页码、游标、返回字段和重试权限不变。
- 新迁移 `028_task_query_indexes.sql` 增加状态/创建时间索引、链接历史任务索引和失败链接部分索引，保留 worker 原有认领、租约、活动唯一性索引。
- 消息列表都先固定频道；移除 `idx_messages_recent`，使用主键反向扫描。状态筛选保留 `idx_crawl_messages_status`。
- 本地 `pansou` 已由 SQLx 应用迁移 **028**，记录耗时 **1187ms**。新迁移设置 5 秒锁等待上限；原迁移及校验和未修改。
- 使用独立维护脚本并发重建 `link_sync_queue` 两个索引，主键由约 11MiB、排序索引由约 19MiB，分别缩至 **16KiB**。最终两个索引均 valid/ready，队列仍为 0 行。
- 消息索引退役约回收 47MiB；新增三个查询索引约 22MiB。合计相关索引净减少约 **55MiB**，不是整个数据库文件大小的稳定承诺。
- 未删除业务行、调整 worker 策略、重启数据库或运行中的 API。已构建新的 debug API；查询代码由下一次后端启动加载，索引维护已经生效。

## 性能对照

最终在本地开发库执行 `BEGIN READ ONLY` 和 `EXPLAIN (ANALYZE,BUFFERS,TIMING OFF)`；SQL 超时 10 秒。旧新查询使用相同目录/任务数据及当前索引。页面查询使用 API 的完整 JSON 字段投影。

| 查询 | 原查询 | 新查询 |
| --- | ---: | ---: |
| 无筛选精确总数 | 98.707ms | 28.876ms |
| 需要关注精确总数 | 85.497ms | 0.200ms |
| 需要关注列表，最多 31 条 | 99.701ms | 1.367ms |
| 无筛选列表，OFFSET 20000、最多 31 条 | 297.414ms | 1.650ms |

这些是少量单次 SQL 观察，包含缓存状态差异和后台负载，不能作为 HTTP P95、冷启动或固定倍数的保证。保留精确 COUNT 和页码意味着海量筛选结果/极深分页仍有扫描成本，没有声称变成常数时间。

另建隔离性能库，从开发库只读复制约 40.8 万条目录、24.7 万条检查任务、134 万条消息。复制时测试库禁用触发器；仅用于执行计划，不将它当成完整的业务一致性数据库。没有复制用户或账号凭据表的数据。

隔离库消息列表 OFFSET 20000，原索引存在时已选择主键反向扫描，约 2.519ms；删除原索引后仍走主键，约 2.404ms，页面内容及排序一致。失败状态筛选继续使用状态索引，约 0.054ms。

候选索引已在隔离库实际命中：`link_check_admin_status`、`link_check_link_history`、`link_catalog_failed_links`；新增大小分别约 9808KiB、12MiB、16KiB。
