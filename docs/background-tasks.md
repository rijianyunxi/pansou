# 链接任务

后台菜单「链接任务」位于 `/admin/tasks`，仅管理链接 worker 的任务。TG 采集继续使用独立的 `/admin/crawl` 工作台，不重复设置分类；管理员直接网盘操作也不混入链接任务。运行监控的链接队列和异常提醒直达相应分类，TG 队列及失败提醒直达 TG 工作台。旧 `/admin/link-cleanup` 地址继续可用。

| 分类 | 记录来源 | 恢复操作 |
| --- | --- | --- |
| 资源链接同步 | 登记采集或编辑后的资源链接，更新资源与链接的对应关系并汇总检测状态 | 暂停后链接登记和状态汇总延后；恢复后自动处理，成功后出队 |
| 有效性检测 | `link_check_jobs` 和当前链接观测 | 重新排队原链接检测；不抢占有效租约，不绕过开关、账号、额度、频率、熔断 |
| 取链 / 转存 | `link_resolve_requests` | 仅查看；不可重放用户授权或重复转存 |
| 链接清理 | `link_cleanup_jobs` | 复用归属核实及到期保护后的安全重试 |
| 过期与超时处理 | 将过期检测结果改为待确认，结束超时取链请求，并清理旧检测、取链与运行记录；列表也显示其他任务失败 | 暂停后周期处理延后，用户查询本次取链请求时仍会检查超时 |

五类任务均使用与 TG 工作台一致的表格、行操作菜单和右侧详情抽屉，移动端仅表格区域横向滚动。任务状态和观测结果分列，详细原因、租约、计划时间、产物归属和文件清单在详情查看。列表统一使用 `AdminPagination`，默认每页 20 条，可选 10/20/50 条，显示筛选后的总数并支持前后翻页、指定页码跳转和 URL 深链接（`page`、`pageSize`）。切换状态、网盘或每页条数回到第一页；后台任务出队导致页码越界时自动回到末页。接口保留旧客户端的时间 + ID 游标及默认每批 30 条。每 10 秒更新，隐藏页面、打开详情或确认框时暂停。读取失败保留当前结果并禁用重试。

Tab 栏上方固定展示「链接后台调度」总开关，以及资源链接同步、有效性检测、链接清理、过期与超时处理四项状态和启停按钮。切换 Tab 只切换任务列表，不重复展示控制区。运行监控的 TG 采集与链接任务卡片统一提供「暂停 / 恢复调度」和「管理任务」：前者分别调用 `crawl` 与 `link-schedule`，后者分别进入 `/admin/crawl` 与 `/admin/tasks`。链接卡片只控制总调度，保留各任务独立开关及检测功能设置；暂停不影响用户按需取链，当前批次继续完成。保存期间禁用重复操作，失败保留原状态并提示重新刷新。旧 `/admin/link-cleanup` URL 保留查询参数重定向到清理 Tab。

| 调度范围 | `PUT /api/admin/runtime/workers/` 后缀 | `background-workers` 字段 |
| --- | --- | --- |
| 链接后台总调度 | `link-schedule` | `linkScheduleEnabled` |
| 资源链接同步 | `link-sync` | `linkSyncEnabled` |
| 后台有效性检测 | `link-check` | `linkCheckEnabled` |
| 到期 / 晚到产物清理 | `cleanup`（兼容 `links`） | `linkEnabled` |
| 过期与超时处理 | `link-maintenance` | `linkMaintenanceEnabled` |

每次只合并所选字段，旧数据新增开关默认启用，不改变 TG 开关和已有清理暂停配置。执行需要总调度与独立开关同时启用；恢复总调度不会开启已独立暂停的任务。暂停在当前批次结束后生效，队列保留，不强制中断云端写入；任务中心的清理或维护独立暂停会延后相应处理，操作前展示确认。维护开关不影响其他通道写入异常记录。

状态使用完整生效条件：检测功能关闭显示「检测未启用」，没有可用于检测的已连接账号显示「无可用账号」，总调度暂停、Worker 离线及状态未知单独显示。「可调度」表示满足领取任务的调度条件，不表示当前正在执行任务。

有效性检测的一般暂停/恢复不修改检测功能开关；功能尚未启用时，点击本页「启用有效性检测」需确认，请求携带 `activateChecks:true`，在同一事务内启用检测功能及独立调度，保留全部频率、额度和缓存参数，失败回滚。总开关和其他任务开关不能携带该标记，不会偷偷启用检测。网盘账号页移除检测启停控件，只保存参数；`PUT /api/settings/link-check` 不传 `enabled` 时通过部分合并保留最新开关状态，防止旧表单覆盖新状态。兼容旧客户端显式 `enabled` 参数，但页面上的启停入口只有任务控制区。

取链 / 转存为用户点击触发，不设置周期调度开关，也不受上述独立开关影响，各网盘的自动转存仍由网盘账号页每张卡片上的转存配置控制。开关以服务端响应为准，失败不显示成功；刷新状态后可重试。

暂停总调度不会停止 API、搜索或 TG 采集。Web 与小程序的复制、打开操作仍走同一取链流程：按网盘配置复用有效分享或检测、转存并生成分享；未启用转存、取链异常或超时可回退原链接，确认原分享失效或资源不存在则提示不可用。暂停期间仍可能产生新转存产物，到期或晚到产物清理会排队等待恢复。检测结果读取时仍按时间判断是否过期，转存分享读取时仍检查到期时间，暂停不会使过期结果永久有效。

状态徽标统一使用图标、文字和颜色：排队琥珀、执行蓝、完成绿、失败红、阻塞橙、暂停灰；明暗主题均校验文字对比度。

「检测已完成」与「链接有效」分开展示；列表观测来自链接当前状态，而非每次任务的历史快照，已过期的观测不再显示为有效。取链采用异步查询，超过后台处理期限才回退原链接展示原因，不等同于任务失败。关闭检测时显示排队不会执行，重新检测按钮禁用，服务端也拒绝请求。任务中心也提示 Worker 离线或状态未知。

迁移 022 增加维护执行历史：记录成功维护批次、其他链接通道失败，不记录每个 2 秒空轮询；同通道同状态至少间隔 30 秒，保留 7 天，维护批次按最多 1000 条清理旧历史。升级前历史无法恢复。只存受控错误分类，不存原始错误、Cookie、Token、授权快照、账号标识或网盘返回体。

## 验证

`cargo test` 和 `frontend` 的 `npm test`、`npm run typecheck`、`npm run build`。隔离集成测试 `task_center_lists_filters_paginates_and_fences_rechecks` 需使用以 `_test` 结尾的数据库及非默认 Redis DB；只使用模拟账号凭据，不请求真实网盘。前端验收页 `frontend/tests/fixtures/tasks-preview.html` 禁止转发真实 API 请求，支持 `scenario=disabled`、`scenario=error` 和含 65 条记录的 `scenario=pagination`。

运行监控验收页 `frontend/tests/fixtures/monitor-preview.html` 使用真实卡片组件和模拟接口，支持 `scenario=failure`（保存失败）、`scenario=slow`（延迟响应）、`scenario=unknown`（调度状态未知）。可直接验证两张卡片的暂停、恢复与管理跳转，接口请求不会转发到真实服务；模拟清理与同步独立开关初始关闭，用于核实总调度操作保持独立配置。
